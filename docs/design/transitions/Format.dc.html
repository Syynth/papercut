The format

What papercut.json holds

Binary assets on disk, map files on their own, everything else in the project file — the ruling of 2026-09-17 is unchanged. What moves is that an image no longer carries a terrain set, and the project carries transitions instead.

Images: art and a grid, nothing else
"images": [
  { "path": "sheets/mapkit.png", "name": "Map kit",
    "firstGid": 1,
    "grid": { "tile": 16, "margin": …, "spacing": … },
    "hash": "sha256:…" },
  { "path": "sheets/walls.png", "name": "Walls",
    "firstGid": 2221,
    "grid": { "tile": 16, … } }
]

An image's terrain is gone. firstGid is assigned when the image is listed and never moves, the way Tiled does it, so a transition's address survives reordering, regridding and relinking.

Materials and transitions
"materials": [
  { "id": 1, "name": "Grass", "color": 6989903,
    "orientation": "floor" },
  { "id": 4, "name": "Wood",  "color": 9136965,
    "orientation": "wall" }
],
"transitions": [
  { "materials": [1, null], "orientation": "floor",
    "at": 1024 },
  { "materials": [1, 2], "orientation": "floor", "at": 1120 },
  { "materials": [1, 4], "orientation": "floor", "at": 5300 },
  { "materials": [1, 4], "orientation": "wall",  "at": 5360 },
  { "materials": [1, 2, 4], "orientation": "any", "at": 2400 }
]

null in materials is nothing, so an edge set needs no special case. The block's shape follows from the length.

GIDs

One number addresses a tile anywhere in the project. An image gets a firstGid when it is listed, reserving as many ids as its grid holds; a tile's gid is that plus its index on the image.

Assigned once and kept. Reordering the image list does not move them, and regridding an image keeps its firstGid while the tiles under it change — the same case the grid remap already handles, now with one place to apply it.
